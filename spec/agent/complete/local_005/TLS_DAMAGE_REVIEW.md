## 8. 初回・継続・再接触

### 8.1 照射の開始と準備

生成・再利用処理`0x147394b10`は、新規生成時の`0x147394ce1`と既存オブジェクト再利用時の`0x147394e21`で、どちらも兵装のvtable`+0x730`を呼ぶ。TLSでは`0x147ef9910 → 0x147ee8990`へ進み、次の状態を初期化する。

| 状態 | 初期化 |
| --- | --- |
| 準備時間カウンター`+0x808` | `-WeaponWarmUpTime` |
| 接触時間カウンター`+0x804` | 0 |
| 初回遅延通過フラグ`+0x80c` | false |
| 前回の目標ポインター`+0x810` | null |
| 命中済み目標の集合`+0x978` | 空にする |

更新`0x147ef8f70 → 0x147ee8870`は、目標判定`0x147ee9840`を先に呼ぶ。準備カウンターが0以下かつ初回遅延未通過なら、float32のdtを足してその更新のダメージ処理を終える。0を超えた同じ更新では命中判定へ進まず、次の更新から初回遅延を数える。準備時間の超過分を初回遅延へ足す処理はない。

準備は照射単位で進み、空振り中も進む。後から目標へ合わせた際に毎回約0.95秒待ち直すものではない。ボタン入力から内部生成までの時間は今回の値に含めていない。

### 8.2 接触の時刻と威力

通常目標への経路は`0x147eea4b0 → vtable+0x780 (0x147f61c20) → +0x750 (0x147eea8c0)`。初回遅延を通過したかという時刻の状態と、その目標へ初めて命中したかという履歴を別に持つ。

| 状況 | 次のダメージ判定 | 被弾処理へ渡す基礎威力（パーツなし / あり） |
| --- | --- | --- |
| 準備後、未命中の目標Aへ接触 | 接触カウンターが約0.05秒を超える更新 | 40 / 46 |
| Aに照射し続ける | 残余時間＋dtが約0.4秒を超える更新 | 18 / 18 |
| Aから外れ、同じ照射でAに再接触 | 接触カウンターを0へ戻し、約0.05秒を超える更新 | 18 / 18 |
| 同じ照射で未命中のBへ切り替える | 約0.05秒を超える更新 | 40 / 46 |
| Bから履歴にあるAへ戻る | 約0.05秒を超える更新 | 18 / 18 |
| 新しい照射を開始しAへ当てる | 準備・初回遅延を経る | 履歴が空なので40 / 46 |

目標変更（nullへの変化を含む）で`0x147eea1e7/0x147eea1ed`が接触カウンターと初回遅延フラグを消す。命中履歴は消さない。履歴は画面の固定IDや名称ではなく実際の目標オブジェクトのポインターをキーにする。同じ掲載行に属する別個体を初回扱いにすることと、同一個体への再接触を区別する。

初回遅延・継続間隔の比較はいずれも`comiss`後の`jbe`で、**等しい間は発生せず、超えた更新で発生する**。発生後はカウンターからその閾値をfloat32で引く。残余時間を保持するが、1回の更新内で回数を取り戻すループはなく、通常目標への通知は最大1回。再接触時は継続間隔より短い初回遅延へ戻るため、照射を外すことが必ず撃破時間を延ばすとは限らない。実際の再接触を連続照射の一定DPSで説明できない理由になる。

`0x147eea8c0`は履歴にない目標ならDamageを選び、**被弾関数を呼ぶ前に**履歴へ追加する。以後はSlipDamageを選ぶ。呼出し側は目標の生存・正のHPを確認するが、無敵などでHPが減らなかった場合に履歴追加を取り消す処理はない。「初めてHPを減らした1回だけ40」とは異なる。

### 8.3 通常被弾・バリア・寿命

初回・継続とも、選んだ威力を同じ目標vtable`+0xa38`へ渡す。LiveAIGameObjectでは`0x147c82df0 → 0x147d0fde0 → +0xa40 (0x147c82f70)`へ接続する。攻撃者とTLSの兵装コンテキストも渡し、既存のROLE・兵装耐性・HP更新を受ける。上表の40/46/18をHP減少量と同一視しない。継続を単純に総和してから一度だけHPを整数化する計算も採用しない。

別経路`0x147eea620`の型照合先は`LivePulseBarrier`。独立した接触状態・タイマーでDamage/SlipDamageを選び、バリア側の値と兵装別係数でHPを書き換える。通常NPC用の履歴集合・ROLE・整数HP更新へ合流する経路ではない。バリアの挙動を通常目標の再接触規則の根拠にしない。バリア自身の全状態遷移・ゲーム内計測は今回の対象外。

寿命は`0x147f602e0`がLifeTimeを`0x147f5fe70`へ渡し、World側のタイマーへ登録する。登録先`0x144b97630`、終了コールバック`0x147f601a0 → 0x147f601b0 → vtable+0x748`を確認した。8秒という資産値を「準備終了後に8秒間、必ず命中できる」とは読み替えない。タイマー終了と兵装更新の同一フレーム内の順序、dtの上限・時間倍率・停止の全条件は未追跡で、厳密な最終命中数の保証は残る。

## 9. 条件付きの時刻例と残る検証

### 9.1 静的処理に沿う計算例

各更新へfloat32(1/FPS)を渡し、開始時から同じ生存目標へ接触し続ける条件で、準備カウンターと接触カウンターを逐次更新した。実ゲームのFPS設定や描画フレーム数から観測した結果ではない。寿命終了・照射範囲・無敵・親子への転送はモデルへ入れていない。

| 入力dtの仮定 | 初回の更新番号 | dt合計による初回時刻 | 次の更新番号 |
| --- | --- | --- | --- |
| float32(1/30) | 31 | 約1.033333秒 | 43、55 |
| float32(1/60) | 61 | 約1.016667秒 | 85、109 |
| float32(1/120) | 122 | 約1.016667秒 | 170、218 |

準備済みの状態にdtをちょうどfloat32(0.05)だけ渡しても初回は起きず、次に小さな正のdtを足すと起きる。dt=1秒なら、その更新の初回は1回だけで、0.95秒の残余を保持する。次のdt=0.01秒では継続1回が起き、残余は約0.56秒となる。

準備済み・dt=1/60・パーツありの`A×4更新 → 空振り×2 → A×4 → B×4 → A×4`では、通知威力は46→18→46→18。新規照射として状態を初期化すると、同じAでも46へ戻る。これらは元命令から作成した条件付きトレースであり、独立した実ゲーム検証ではない。

### 9.2 追加解析と実ゲーム測定の切り分け

| 区分 | 項目・今回の到達点 | 次の作業 |
| --- | --- | --- |
| 静的確認済み | TLS.POW+は初回だけ、履歴と時刻状態の分離、再接触、strict比較、float32、超過分、生成・再利用時の初期化、通常NPC被弾への接続 | 追加の実測なしでも、条件を明示した計算仕様の根拠にできる |
| 追加解析で詰められる | dtの生成元・上限・時間倍率、Worldタイマーと兵装更新順、射程・半径曲線・遮蔽・多部位の選択規則、バリア専用状態 | 現行の更新管理・衝突問い合わせ・タイマー処理を対象にする。今回資産不足で止まった項目ではない |

実測するなら、まず同じ目標・ROLE・距離でTLS.POW+なし/ありの初回だけを比較し、継続部分の差がないことを確認する。次に同一照射でA→空振り→AとA→B→Aを比較し、最後に新規発射で初回が戻ることを確認する。撃破までの総時間1点だけでは、パーツ・再接触・整数HP更新のどれが原因かを切り分けられない。

## 10. 配信反映を検討する際の候補（掲載判断前）

現行の固定ID33・`calculation: tls`・既知値・`unknown`表示は変更していない。今回見つかったパーツの非適用は、まだ数値を返していない現行アプリの計算不具合として扱わない。

次の候補は「生存する同一目標への連続照射」を条件とする理論値の仕様整理。初回40/46と継続18を個別に補正・HP更新し、時間の起点を「接触から」か「内部照射開始から」か明示する。表示単位を秒数にする場合はdt条件・丸めも必要であり、今回の調査だけで一意の連続時間式を決めない。照射切断・目標切替・複数回の発射を混ぜた最短撃破時間は別の問題になる。

配信反映を急がず追加確認する候補としては、dtと寿命末尾の更新順の追跡、または上記の小さい実測比較がある。どちらを選ぶか、TLSの画面上の評価単位をどう定義するかは今回の結果を見て判断する。
