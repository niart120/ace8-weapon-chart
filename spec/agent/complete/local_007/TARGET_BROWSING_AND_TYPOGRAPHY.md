# 対象選択・比較表・書体の改善仕様書

## 1. 概要

### 1.1 目的

敵を種別または出現ミッションから選び、必要命中数を比較しやすくする。Rajdhaniを採用し、表と操作部の文字サイズ・太さ・余白を見直す。

### 1.2 用語定義

| 用語 | 定義 |
| --- | --- |
| TYPE | 対象種別・細分類から敵を個別選択する方式 |
| MISSION | 選択任務のいずれかに対応する敵を表示する方式 |
| 細分類 | 機体マスタの分類、または表示のために編集した用途・形状の分類。ダメージ計算のROLEとは独立 |
| 初期順 | 結果表ではHP昇順、同値は名前・固定ID順 |

### 1.3 背景・問題

既存の対象検索は名称のみ。任務差分の有無と全出現任務の対応は異なる。AIRCRAFTなどの分類が大きく、表の見出しから並べ替えられない。文字サイズはPCの表12px、モバイル11pxと小さい。

### 1.4 期待効果

| 項目 | 期待効果 |
| --- | --- |
| 対象選択 | 隠れた別方式の条件を適用せず、TYPEとMISSIONを切り替えて探せる |
| 比較 | 列ごとの並べ替えと命中数の固定5区分で差を読み取れる |
| 文字 | 狭い画面でも本文を縮小せず、横スクロールで表を閲覧できる |

### 1.5 着手条件

ユーザー合意済み。TYPE/MISSIONは選択中の方式だけを適用し、非アクティブ方式の選択を保持する。確認可能な機体はゲーム内分類を採用し、それ以外の目標の分類は実装者の裁量とする。コミット・公開は今回の作業に含めない。

## 3. 設計方針

- UIに説明文、状態要約、件数などを追加しない。既存のWEAPONS/TARGETS入口とパネル形式を維持し、TARGETS内にTYPE/MISSIONタブを置く。独立したMISSIONSボタンは作らない。
- 絞り込みは即時反映。タブはキーボード操作にも対応する。
- 出現任務の対応と任務固有の性能差分は別属性にする。元資料の参照先や分類根拠は配信用データに含めない。
- 公開前のため旧保存への変換は実装しない。保存形式を更新し、旧形式は初期化する。
- 計算式、固定ID、公開・除外方針は変更しない。

## 4. 実装仕様

### 4.1 対象データ

対象に`missionIds`と`subcategory`を追加する。任務別の既存出典を優先し、子NPC・部位の対応を辿って補完する。根拠のない任務は推測で追加しない。静的定義との対応であり、全配置・イベント発火の実ゲーム確認とは区別する。対応を得られない対象と分類の編集判断は別の調査記録に残す。

AIRCRAFTはFIGHTER/MULTIROLE/ATTACKER/ELECTRONIC WARFAREの確認可能なゲーム内分類を優先する。爆撃機・支援機・回転翼・UAV・特殊機などを補う。地上は防空・装甲・砲兵・支援など、艦船は主力艦・小型艦・輸送など、構造物は軍事施設・燃料/産業などで整理する。部位はPARTSに分ける。最終分類を調査記録に列挙する。

### 4.2 選択方式

- TYPE: 種別→細分類→対象。分類内はHP昇順、同値は名前・ID順。検索は候補一覧だけに作用。既存の部位・任務差分表示を維持する。
- MISSION: ゲーム内の番号順のチェックボックスで複数選択。空選択は任務で絞らない。対応する掲載対象のないPROLOGUEは無効表示とする。TYPEの個別選択・部位/任務差分非表示設定は適用せず、該当任務の部位・性能差分を含む掲載対象を表示する。
- 方式切替前の選択を保持する。TARGETSリセットで方式をTYPE、個別選択を全対象、任務選択を空、部位/任務差分表示をオフへ戻す。
- 一括操作は分類単位。名称検索中でも同じ分類全体を対象とし、検索文字列自体は選択状態を変更しない。

### 4.3 ソート

TARGET、HP、各兵装の見出しをボタンにする。クリックで昇順→降順→初期順。ソートは1列のみ。HPの昇順は初期順と同じため、初期状態からHPを押すと降順、その次は初期順へ戻る。TARGETは名前、HPは数値、兵装は計算結果の数値で比較する。`-`（ダメージ0）、`?`（未確認）は数値の後に置き、昇降順にかかわらず末尾。数値同値は初期順で安定させる。`aria-sort`と矢印で方向を示す。兵装が非表示になった場合は初期順に戻す。計算条件変更時は現在のソートを新しい値に適用する。並べ替え状態は保存せず、全体リセットで初期順に戻す。

### 4.4 色と書体

命中数1/2/3/4/5以上の固定5区分で文字色を付け、数値は省略しない。未確認・ダメージ0は中立色とする。明暗両テーマで文字のコントラストを確認する。凡例や説明文は追加しない。

Rajdhaniの400/500/600をOFL 1.1に基づき自己配信し、著作権・ライセンスを同梱する。英数字の本文・表・操作部に使用し、日本語は既存OSの日本語書体で補う。表15px、操作部16px、補助ラベル13px、見出し18〜24pxを初期案とし、ブラウザー確認で調整する。モバイルで表本文を縮小しない。

### 4.5 性能要件

| 対象 | 要件 |
| --- | --- |
| 計算 | 並べ替え比較関数内で再計算せず、1描画で各セル1回の計算に抑える |
| 配信 | 起動時の外部フォント通信・元調査資料へのアクセスを不要にする |
