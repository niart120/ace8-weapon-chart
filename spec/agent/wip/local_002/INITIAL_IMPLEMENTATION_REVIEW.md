## 4. 実装仕様に対する指摘

### R001 / P1 / 確定: 通常MSLが機銃用の耐性を参照する

対象: [resolve-reference.py](../../../../scripts/generate-data/resolve-reference.py):46、[weapons.json](../../../../src/data/weapons.json):388、[targets.json](../../../../src/data/targets.json):4575。生成用定義のMSLとGUN/MGPがともに`standardMissile`を指定している。

再現条件は、FIGHTER・パーツなし・DIRECTで通常MSLを選び、X-40（ID 457、HP300）を見ること。実装は30発を返すが、元データに対応する値は6発。X-40の通常耐性`x40a_WPDur_000`では、MSLが参照する`Category01`は100、機銃が参照する`Category02`は20である。MSLの威力40にROLE補正1.25とMSL耐性1を適用すると1発50となる。

生成処理が倍率キーから耐性列への対応を順に代入し、後のGUN/MGPで`standardMissile`の参照先を`Category02`へ上書きする。その値をMSLとRookie版MSLも使ってしまう。GUN/MGPの参照列は正しく、問題は異なる耐性列のキー共有にある。

| 目標 | 条件 | 実際 | 期待 |
| --- | --- | ---: | ---: |
| X-40、HP300 | 通常MSL、FIGHTER、パーツなし、DIRECT | 30 | 6 |
| LADON、HP1200 | 同上 | 48 | 24 |
| AIRSHIP、HP235 | 同上 | 24 | 5 |

影響: EXCLUDED以外の46行でMSL用の倍率が元の`Category01`と不一致。そのうち上の条件で数値が変わるものは36行、残る10行は別の未確認条件により`?`となる。通常MSLとRookie版MSLの比較・パーツ選択に誤った判断を生じさせる。

根拠: 初期設計4.7（642行）は、数値が偶然一致するだけでは倍率キーを共有せず、同じ耐性参照先を使う成分で共有すると定める。`DT_LiveWeapon`のMSLは`WeaponDurabilityCategory=1`、GUN/MGPは2。`DT_NPC_WeaponDurability.json`の`x40a_WPDur_000`は151行から確認できる。

修正後の確認事項: MSLとGUN/MGPの参照先を分離し、同じキーに異なる列が割り当てられた場合を生成時に検出する。X-40などの固定期待値は元の列から独立に導出する。追加照合では、現在統合された同一行の`sourceRefs`内に、失われた`Category01`の差がある例は見つからなかった。

### R002 / P2 / 確定: 条件の違う同名行を識別できず、任務差分を非表示にできない

対象: [targets.json](../../../../src/data/targets.json):4354（TYPHOON ID 333）、7480（AEGIS ID 341）、8600（FRIGATE ID 364）、`data/local/catalog.json`:3896、6494、7414。初期登録処理の`data/local/bootstrap.py`:109–112も該当する。

FIGHTER・パーツなし・DIRECT、`MISSION VARIANTS`オフの初期状態で、同じ名前・HPのTYPHOONが2行表示される。選択パネルも両方が`TYPHOON 60`となる。ID 95は通常設定、ID 333はM25後半のSHADOW用設定で、UAVT倍率だけが1と0.25で異なる。後者の出典は`DT_NPC_Mission025day2/typn_Shadow_MS25day2_01`と`_02`、NPC耐性は`Shadows_WPDur_000`。別行にする根拠はあるが、どの設定かを画面から選べない。

現在UAVTは常に未確認表示であるため、この2行は全34掲載兵装の初期条件で表示結果も一致した。数値が同じことを理由に統合するのではなく、条件を識別できるラベルを付け、任務固有の行には表示切り替えを適用する必要がある。

同じ欠落はM25後半のAEGIS・DESTROYER・FRIGATEとその部位にもある。FRIGATEのID 56と364はともにHP75・任務ラベルなしだが、上の条件でMGPはそれぞれ18発・35発になる。M25後半用の本体3行・部位8行（計11行）にも`missionVariant`がない。

原因: 初期登録では任務行を「その任務が参照する同一NPCの共通設定」とだけ比較する。任務専用NPC自体に埋め込まれた耐性差は一致と判定され、通常NPCとの違いが任務差分・表示名へ反映されない。

根拠: 初期設計3.1（72–84行）は、同名でもHP・耐性が異なる場合に条件の分かる別行とし、耐性だけの任務差分もラベルと表示切り替えの対象にする。3.4（126行）はミッションラベルを定める。

追加調査: EXCLUDEDを除いて同一分類・同名・同HPで集計すると34組69行あり、全組に計算データの差があった。TYPHOONと同じくUAVT倍率だけが違う航空機は12組。全組を任務差分と断定するものではないが、条件を識別できない表示は共通する。IDと差分は[目標掲載範囲の追加監査](TARGET_SCOPE_AUDIT.md)に記載した。

利用者への影響: 同じ選択肢のどちらが実際の目標に対応するか判断できず、任務差分をオフにしても固有設定が通常設定に混在する。

修正後の確認事項: 固定ID・元定義対応を維持して通常設定と固有設定を識別する。TYPHOONとM25後半の艦船について、ラベル・表示フラグ・確定数を元定義と照合する。名前・HPや現在の計算結果だけで統合しない。

### R003 / P2 / 確定: CELAENOとTRIUMPHANTの8部位が独立目標になっている

対象: [targets.json](../../../../src/data/targets.json):1970、2001、4230、4544、4765、5236、8879、9003。`data/local/bootstrap.py`:95–101、115–120、126–132。

| 本体 | 部位・ID | 現在の分類 |
| --- | --- | --- |
| CELAENO | MAIN ENGINE 473、MAIN PROPELLER 474、SUB PROPELLER 475、WING SPAR 476 | AIRCRAFT |
| TRIUMPHANT | AA GUN 483、DISP. RAIL GUN 484 | GROUND |
| TRIUMPHANT | NAVAL GUN 485、LAUNCH TUBE 486 | SHIP |

再現条件は`TARGET PARTS`をオフにした初期表示。8行とも`partOf:null`で本体名がなく、そのまま表示される。TRIUMPHANTのAA GUNとDISP. RAIL GUNはGROUNDの一括操作に含まれ、SHIPの一括操作では選択できない。

元の`ChildNPCId`には親子関係がある。例えば`OP0044_cleo_01 → OP0049_cleo_MainWing_BL → OP0049_cleo_MainEngine_BL`をたどれる。初期登録が表示名のない中間NPCで処理を終了して子を巡回せず、後のガイド対応による登録で子だけを本体なしの目標にしている。TRIUMPHANTのハッチを挟む部位でも同様の欠落がある。

期待する挙動は、各行を`部位名《本体名》`とし、`TARGET PARTS`で表示を切り替えること。艦船部位はSHIPへ分類する。部位自身のHP・耐性・計算属性は維持する。

根拠: 初期設計3.1（78–84行）、3.4（124行）、3.9（238–242行）。同梱NPCの子参照と整理済みガイドの部位記載。

利用者への影響: 部位を隠せず、どの大型兵器の部位か識別できない。分類選択でも対象を取り違える。

修正後の確認事項: 表示名のない中間定義を越えて親子関係を確認し、同条件の左右部位を既存方針どおり統合する。今回確認した8行以外の参照欠落も、別条件の登録漏れなのか同条件の統合漏れなのかを区別して監査する。

### R004 / P2 / 確定: PCでSpace・Enterを押すと選択パネルが閉じる

対象: [Panel.tsx](../../../../src/components/Panel.tsx):57–65。

Chrome、1440×1000でWEAPONSを開き、MSLのチェックボックスへフォーカスしてSpaceを押すと、選択変更と同時にパネルが閉じ、WEAPONSボタンへフォーカスが戻る。MSL.AIR分類見出しへフォーカスしてEnterを押した場合も閉じる。

子要素から伝播したキーボード由来のclickに対し、ダイアログ全体が`clientX/clientY`と外枠の座標だけで外側クリックを判定している。座標0,0がPCの右側パネル外と判定されるためである。

期待する挙動は、パネル内の選択・分類展開では開いた状態を保ち、次の項目もキーボードで操作できること。根拠は初期設計3.8の複数選択操作と6.4（928行）のキーボード操作確認。利用者は項目を操作するたびにパネルを開き直す必要がある。

修正後の確認事項: Spaceによるチェック、Enterによる分類展開、閉じるボタン・Escape・実際の外側クリック、フォーカス復帰を個別に確認する。Chrome 156.0.8078.74で追加再現済み。

## 5. 判断保留・未検証事項

### Q001 / 掲載判断保留: QUEEN・GREENおよび追加の味方候補

既存の合意済み199任務行に対する除外漏れは確認していない。今回の表示対象はその集合と別の元定義であり、既存の除外仕様への単純な実装違反とは区別する。

ただし、既存調査の検索対象だった任務行キー・NPC ID・モデルID・Blueprint名以外に、モデルやNPCの表示名キーに`ContainerAllyCallsign_*`がある。追加検索では既存の除外対象外で43任務行、統合後20表示行が該当した。内訳はQUEEN 36行、PURPLE MAGIC 4行、GREEN 1の1行、ENDURANCEに対応するAIRCRAFT CARRIER 2行。

QUEENの表示対象はF/A-18C系で、既にEXCLUDEDのF/A-18E系PV用QUEENとは別定義。GREENはM28の味方用NPCが既にEXCLUDEDである一方、M15のGREEN 1は味方を示唆する呼称キーのNPCと敵を示す呼称キーのNPCが同じ行に統合されている。GREEN 2のM15定義も敵用の呼称キーを持つ。

命名上の手掛かりは静的に確認したが、実際の所属・出現・掲載可否は未確定。表示名全体を一括除外せず、[追加監査の対応表](TARGET_SCOPE_AUDIT.md)を基に任務行単位で扱いを決める必要がある。これらをEXCLUDEDへ変更する決定は本レビューでは行っていない。

R005の3つのNPCは`BP_GR000_dummy_CP_C`を参照する。対応する任務行も掲載されており、AIR BASE [M28]（ID 456）、APC [M13]（ID 199）、LAND BATTLESHIP 2 [M20]（ID 261）は任務側の耐性で数値を返す。最後の行の出典名は`GR037_ldbs2_ScoreDummy`。
